## High-level view

The classification fix is real and precise. `_classify_changes` examines only params validate actually moved (`valid != stepped`), then partitions them by whether a nudge or the coordinate step had already moved them from the pre-nudge base: unchanged-from-base means pure repair, changed-from-base means collision. `propose_next` returns the 5-tuple `(valid, notes, repair_names, repair_only, collision)` with `repair_names = repair_only | collision`, so the delta routing in `run()` still sends every validate-changed param to `repair_delta` while the notes distinguish the two origins. The "not a nudge" wording is now emitted only for `repair_only`, and collisions carry "repair overrode nudge" alongside the surviving `pf<1` diagnosis note, so the log no longer contradicts itself.

The README first-run section was rewritten to match. It walks the operator through the actual two-step StopLoss move on the real baseline (pf<1 tightens 1000->900, ordering-repair raises to 1800, net 1000->1800), states plainly that a diagnosis rule did target StopLoss and the repair just won, and reserves the "not a nudge" note for the PF>=1 pure-repair case. The doc now describes behavior instead of overclaiming it.

The four new tests lock the three origin cases and the union invariant. The collision test pins StopLoss into `repair_names` and `collision` (not `repair_only`) with the "repair overrode nudge" note and the surviving pf<1 note; the pure-repair test drives StopLoss into `repair_only` under benign metrics; the pure-nudge test confirms a nudged-and-survived Risk_Percent stays out of every repair bucket; the union test asserts `repair_only` and `collision` are disjoint and cover `repair_names`. Reverting `_classify_changes` to the old behavior (everything into `repair_only`) makes the collision test fail, so the tests have teeth.

### Three-way classification is correct and the collision case is expressible

`_classify_changes` takes the pre-nudge `base`, the post-nudge/step `stepped`, and the post-validate `valid`. It ignores any param validate left alone (`valid == stepped`), then for each remaining param checks `stepped != base`: true means a nudge or the coordinate step moved it and validate then overrode that move (collision), false means only validate touched it (pure repair). This is exactly the signal the v2 gap needed. The old predicate ("did validate move it") could not distinguish a repaired-only param from a nudged-then-repaired one, so it labelled the collision case "not a nudge"; the three-snapshot comparison recovers the missing nudge information without changing which value gets written.

Routing is sound. `run()` still splits the old-to-final `delta` on membership in `repair_names` (= `repair_only | collision`), so a collision param keeps its full old->final move in `repair_delta` -- the final written value is what an operator cares about -- while the note layer carries the honesty. The dry-run against the real v2.11 baseline (`reports/round01_20260913.summary.json`, PF 0.58) confirms it:

```
repair_delta={"StopLoss_Pips": [1000, 1800]}
notes=... pf<1: tighten StopLoss, lower T1; coordinate-descent: step Min_EMA_Distance up;
       repair overrode nudge: StopLoss_Pips
```

There is no "ordering/bounds repair (not a nudge): StopLoss_Pips" note in this case -- the false claim v2 flagged is gone. The pure-repair path still works: the dry-run against `reports/samples/sample_report.summary.json` (PF >= 1, pf<1 rule does not fire) emits `repair_delta={"StopLoss_Pips": [1000, 1800]}` with `ordering/bounds repair (not a nudge): StopLoss_Pips`, which is the correct label when no nudge touched StopLoss. Both dry-runs wrote no files (no `logs/` dir created, git status unchanged).

### Tests genuinely lock the classification

The collision test seeds the invalid v2.11 vector (T3=1800 > StopLoss=1000) with pf<1 metrics and asserts StopLoss lands in both `repair_names` and `collision`, is absent from `repair_only`, carries the "repair overrode nudge: StopLoss_Pips" note, does NOT carry a "not a nudge): StopLoss_Pips" note, and still shows the pf<1 diagnosis note. That last pair of assertions is what pins the fix: it fails under the exact defect v2 described. Reverting `_classify_changes` to funnel every validate-changed param into `repair_only` reproduces the old output (StopLoss in `repair_only`, "not a nudge" note present), which fails this test -- so the guard has teeth rather than just re-asserting current output.

The pure-repair test leans on the deterministic coordinate step: at iteration 0 the step targets index 0 (Risk_Percent), not StopLoss, so with benign metrics no rule fires on StopLoss and validate alone raises it -- landing it in `repair_only`. The pure-nudge test starts from a legal vector (T3=900 <= StopLoss=1000) so ordering-repair stays quiet, trips dd>15 to cut Risk_Percent, and sets iteration 9 so the coordinate step hits Entry_Cooldown_Bars rather than stepping Risk_Percent back up; it then asserts Risk_Percent survives at 0.75 and appears in none of the three buckets. Those index choices (0 -> Risk_Percent, 9 -> Entry_Cooldown_Bars) match `PARAM_NAMES`, so the tests exercise the paths they claim. The union test closes the invariant the delta routing depends on: `repair_only` and `collision` are disjoint and their union equals `repair_names`, so no repaired param leaks out of the split.
