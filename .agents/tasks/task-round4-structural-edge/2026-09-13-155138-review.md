## High-level view

The v1 blocking defect — the fixed-point tiers (500/1000/1800 pts) sitting far above a typical ATR TP (~250-750 pts on M5 gold), which killed the runner the round exists to test — is resolved. `ManageTargets()` now derives effective thresholds `t1Thr/t2Thr/t3Thr` that default to the fixed `Tx_Pips` but switch to `ATR_Tx_Mult*ATR/_Point` when `Use_ATR_Dynamic_SLTP && Use_ATR_Scaled_Tiers` and ATR is ready. With mults `0.8 < 1.5 < 2.2 < 2.5 (ATR_TP_Mult)`, T1/T2 bank and the after-T2 trail arms inside the hard TP, and T3 full-closes just before it. The three tier comparisons use the effective thresholds; the fixed `Tx_Pips` remain the fallback, so the 11 tuner inputs are untouched in name/type/line-form and the change is reversible via the switch.

The reversibility wording is corrected in both the source banner and the log: legacy behavior now explicitly requires all four of `Use_Confluence_Entry`, `Use_ATR_Dynamic_SLTP`, `Use_ATR_Regime_Filter`, `Use_Session_Filter` to be false, matching the fact that regime and session are independent gates.

The R:R clamp fix re-derives `tpDist = slDist * (ATR_TP_Mult/ATR_SL_Mult)` after `slDist` is clamped up to the broker stops-level, so the ~1.67 ratio survives low-ATR conditions instead of collapsing toward 1.0. Signs are correct in both directions (BUY: SL below, TP above; SELL: SL above, TP below).

The pullback scans in both `BullPullbackResume` and `BearPullbackResume` now start at `i=2`, excluding the resume bar (index 1) so a single straddling candle cannot double-count. The guarded Copy count `Pullback_Lookback+2` still covers the highest index read (`Pullback_Lookback`), and the loop bound is correct.

### ATR-scaled tiers close the runner gap (v1 item 1, blocking)

`ManageTargets()` opens by computing effective thresholds:

```
double t1Thr = (double)T1_Pips;
double t2Thr = (double)T2_Pips;
double t3Thr = (double)T3_Pips;
if(Use_ATR_Dynamic_SLTP && Use_ATR_Scaled_Tiers)
{
   double atrNow = GetATR();
   if(atrNow > 0)
   {
      t1Thr = ATR_T1_Mult * atrNow / _Point;
      t2Thr = ATR_T2_Mult * atrNow / _Point;
      t3Thr = ATR_T3_Mult * atrNow / _Point;
   }
}
```

The T1/T2/T3 comparisons (`pips >= t1Thr`, `t2Thr`, `t3Thr`) all use the effective thresholds. When the ATR path is off, `Use_ATR_Scaled_Tiers` is off, or ATR is not ready, they fall back to the fixed `Tx_Pips`, so the tuner-managed inputs keep their exact name/type/single-line form and the behavior is reversible. Because `ATR_T1_Mult(0.8) < ATR_T2_Mult(1.5) < ATR_T3_Mult(2.2) < ATR_TP_Mult(2.5)`, T1 and T2 partials bank and `ApplyTrailingToTickets(t2_tickets, ...)` arms the after-T2 runner trail before the broker-side hard TP can pre-empt it — which is exactly what v1 flagged as structurally dead.

The T3-vs-TP interaction is coherent, not a bug: T3 at `2.2*ATR` issues a full `PositionClose` a hair before the hard TP at `2.5*ATR` would fire. By the time price reaches `2.2*ATR` the after-T2 trail (armed at `1.5*ATR`) has already been protecting the remaining volume, so the runner is banked with a protective stop underneath it and closed by the EA slightly inside the broker target rather than being carried flat to the hard TP. The tiers now describe a protected-runner exit, which is what the round set out to test.

### R:R preserved under the stops-level clamp (v1 item 3)

Both directions clamp the SL distance up to the broker minimum first, then re-derive the TP distance from the (possibly clamped) SL:

```
double slDist = ATR_SL_Mult * atr;
if(minStop > 0 && slDist < minStop) slDist = minStop;
double tpDist = slDist * (ATR_TP_Mult / ATR_SL_Mult);
if(minStop > 0 && tpDist < minStop) tpDist = minStop;
```

`ATR_TP_Mult/ATR_SL_Mult = 2.5/1.5 = 1.67`, so `tpDist` is always 1.67x the effective `slDist`; the ratio survives even when the raw ATR SL was below the broker floor. The residual `tpDist < minStop` guard only fires if 1.67x the min-stop is somehow still below the min-stop, which cannot happen for a positive `minStop`, so it is a harmless belt-and-suspenders check that never degrades the ratio. Signs are correct: BUY sets `sl = ask - slDist`, `tp = ask + tpDist`; SELL sets `sl = bid + slDist`, `tp = bid - tpDist`.

### Reversibility wording (v1 item 2) and pullback window (v1 item 4)

The header banner now states legacy behavior requires setting `Use_Confluence_Entry`, `Use_ATR_Dynamic_SLTP`, `Use_ATR_Regime_Filter` and `Use_Session_Filter` all false, explicitly noting the confluence and ATR SL/TP switches alone leave the regime and session gates active. The ITERATION_LOG carries the same corrected wording. This matches the actual gate structure (`SessionOK()` and the `Use_ATR_Regime_Filter` block sit above the entry-selection branch with their own default-true switches).

Both pullback helpers scan `for(int i = 2; i <= Pullback_Lookback; i++)`, excluding the resume bar at index 1 so the fresh-pullback-then-resume semantics hold. The guard fetches `need = Pullback_Lookback + 2` elements (indices `0..Pullback_Lookback+1`), covering the highest index the loop reads (`Pullback_Lookback`) plus the `[1]` resume-bar read, so the length guard `< need` is sufficient and the loop bound is in range.

### No regression in the previously-good properties

`atr_handle` is created only when `Use_ATR_Regime_Filter || Use_ATR_Dynamic_SLTP` and `rsi_entry_handle` only when `Use_Confluence_Entry`, both guarded against `INVALID_HANDLE` with `INIT_FAILED`, both released in OnDeinit. `GetATR`, `GetEntryRSI`, and both pullback helpers length-guard every `CopyBuffer`/`CopyClose`/`CopyHigh`/`CopyLow`. Trade calls use the correct `(lots, _Symbol, price, sl, tp, comment)` signature; `_Digits`/`_Point` usage is consistent. Version is `2.12` everywhere (banner, `#property copyright`, `#property version`, OnInit/OnDeinit prints, dashboard title, `EA_Comment`) with zero `2.11` remaining. Brace and paren deltas are 0.
